# Vibe Marketing B2B Deliverables

Use this reference to decide what to produce, what must be included, and what quality bar applies. The default business context is selling a 科创赛考 course/product-line system to B-end education or training institutions.

## Default Strategic Standard

Every deliverable should answer four questions:

- Who is this for? Name the institution type and buyer.
- What business pain does it hit? Use concrete operating scenes, not abstract anxiety.
- Why is 科创赛考 relevant now? Explain fit timing and product-line logic.
- Who is not suitable? Add a filter to reduce invalid leads.

Do not confuse C-end parent desire with B-end institutional pain. For B2B content, children's emotions matter only when they explain an owner-facing problem such as renewal, visible outcomes, parent trust, or product-line upgrade.

## Creation Sequence and Skipping Rule

Default sequence for a full platform content item:

1. Structure the user's topic input.
2. Diagnose target institution, buyer, real pain, fit timing, and unsuitable leads.
3. Choose the content type and core point of view.
4. Draft the single-post package: title, editor's note, lead-quality filter, and 5 related hot tags.
5. Design the cover as the video's first frame.
6. Create the editable short-video design draft.
7. Wait for the user's draft confirmation unless explicitly told to proceed.
8. Check production dependencies and commercial-use assumptions when rendering is requested.
9. Confirm voiceover terms when narration contains mixed Chinese-English terms or technical terms.
10. Produce the rendered video.
11. QA the video, first-frame cover, editor's note, tags, and final files.

If the user has already provided a specific target institution, buyer, title, pain point, platform, product, hook, visual direction, or delivery format, skip the corresponding discovery step. Do not ask the user to repeat information that is already clear. Instead:

- Restate the provided information as a structured brief.
- Mark which elements are locked and should not be changed silently.
- Identify only missing assumptions that materially affect lead quality, platform compliance, or production.
- Continue to the next deliverable in the sequence.

## Default Final Package

For a full Xiaohongshu/Douyin-style B2B content item, the final deliverables are:

- Rendered short video.
- Cover integrated as the video's first frame, not a separate unrelated cover concept.
- Editor's note/body copy.
- Exactly 5 related hot tags.

The video first frame should carry the approved cover title and visual signal. If a separate image file is also exported for upload convenience, it must match the first frame's title, hierarchy, and core visual unless the user explicitly requests a platform-specific variant.

## Deliverable 1: Opportunity Positioning

Use when the user asks whether a target institution type is suitable, or asks for an overall angle.

Must include:

- Target institution and current business model.
- Existing assets that make 科创赛考 possible: parent base, trust, teachers, classroom space, student ability, service capacity.
- Real pain scene: what happens in enrollment, renewal, parent communication, teacher delivery, or成果展示.
- Fit timing: when adding 科创赛考 is appropriate.
- Unsuitable cases: who should not do it yet.
- One-sentence positioning.

Quality bar:

- Must sound like a business diagnosis for an owner, not a course introduction.
- Must avoid claiming 科创赛考 is naturally suitable for every institution.

## Deliverable 2: Content Matrix

Use when the user asks for batch planning, account direction, or multiple topics.

Must include:

- Content pillars: industry judgment, institution pain, solution disassembly, scenario proof, cooperation invitation.
- Each topic's target reader, pain, title angle, platform format, and lead-quality filter.
- Separation between awareness posts and conversion posts.

Quality bar:

- Do not include topics that attract mismatched leads just because they are click-friendly.
- If a topic may bring invalid咨询, mark it as risky or exclude it.

## Deliverable 3: Complete Single-Post Package

Use when the user asks for one content item such as "给某类机构做一条科创赛考合作内容".

Must include:

- Title or cover headline.
- Cover/first-frame design: platform ratio, title hierarchy, visual subject, text-safe area, and what must not be covered.
- Editor's note/body copy: usually 100-200 Chinese characters when requested for Xiaohongshu; concise, credible, and self-screening.
- Exactly 5 related hot tags for the target platform and topic.
- Short-video design draft: an editable Markdown file for user revision before rendering; include narration, scene-by-scene visual design, pacing, and QA notes.
- Lead-quality filter: who should continue reading and who is not suitable.
- Platform compliance notes when relevant.

Quality bar:

- One post should have one point of view.
- The opening should make the B-end owner feel "this is about my school/business".
- Do not turn the post into a generic招商 ad.

## Deliverable 4: Xiaohongshu Cover or Image Set

Default format:

- 9:16, 1080 x 1920.
- For covers, the core title/subtitle/key visual must sit within the middle 3:4 thumbnail-safe area defined in `cover-formulas.md`.
- Use a real or realistic education/business scene first, then deterministic local typography.

Must include:

- One short high-impact title.
- One supporting qualifier or filter when needed.
- Visual evidence: people, classroom, project work, parent communication, product-line path, or成果展示.
- When paired with a video, the cover should normally be the video's first frame and match the video opening hook.

Hard requirements:

- Do not rely on AI-generated Chinese text as final text.
- Do not cover faces, hands, project work, parent expressions, teacher actions, or the visual contrast that explains the scene.
- Do not use large full-width masks or bottom panels merely to make text readable.
- Text chips, bubbles, and panels must be sized from actual text length and aligned visually.

QA:

- Inspect full 9:16 image.
- If the artifact is a Xiaohongshu cover, verify the middle 3:4 safe area or use the safe-area coordinates.
- Check punctuation, line breaks, no single-character orphan lines, and no generated-text remnants.

## Deliverable 5: Toutiao Cover

Default format:

- Dedicated 4:3 landscape cover.
- Do not crop a Xiaohongshu cover into Toutiao format.

Must include:

- The approved title if one exists.
- One supporting phrase or filter at most.
- A clear business scene or outcome visual.

Quality bar:

- It should look like a business/opinion article cover for an owner browsing a feed, not like a vertical social poster forced sideways.
- Preserve the approved hook; do not rewrite it into a more explanatory article sentence unless asked.

## Deliverable 6: Short-Video Design Draft

Use when the user asks for a short video, rendered video, Remotion/HyperFrames production, or wants to revise video details before production. Read `video-design-draft.md` first.

Must include:

- Editable Markdown file saved under `outputs/<task-folder>/video_design/`.
- Basic setup: target buyer, institution type, platform ratio, planned duration, tone, core point, and source cover/materials.
- B-end diagnosis: real pain, qualified audience, unsuitable leads, timing, and low-risk next step.
- First-3-seconds hook design: picture, voiceover, on-screen text, visible motion/information change, and why it fits the target buyer.
- Scene-by-scene structure: time range, shot size/viewpoint, picture, on-screen text, case/evidence overlay, exact production-ready voiceover, motion, layout notes, and QA risks.
- Visual, subtitle, sound, voiceover-term, publishable-copy, and risk-boundary sections.
- Pending confirmation items the user can directly edit before production.
- Explicit design-draft confirmation status before moving into voiceover, image generation, Remotion/HyperFrames work, or rendering.

Quality bar:

- The design draft should be specific enough that Remotion/HyperFrames production can follow it without re-deciding the business logic.
- Do not generate images, synthesize voiceover, implement the video, or render before the draft is approved unless the user explicitly asks to skip this step.
- It must stay B-end facing and avoid C-end parent advice unless parent behavior is used to explain an institution operating pain.
- Shot design should vary across the video. Use wide, medium, close-up, extreme close-up, over-the-shoulder, top-down, screen/board, and abstract logic views deliberately so the viewer does not tire of one repeated composition.
- Voiceover in the draft must already handle terminology and English localization decisions. Unresolved pronunciation or translation choices belong in the confirmation table, not in the production script.

## Deliverable 7: Short-Video Script

Use when the user asks for short-video content but not necessarily rendered media.

Must include:

- Target platform and ratio.
- First-3-seconds hook design: voiceover opening, on-screen text, and visual change must work together to stop the target B-end buyer in the feed.
- Voiceover script or segment-by-segment narration.
- Scene list with visual logic.
- On-screen text for each scene.
- Approximate timing per scene.
- Optional case/evidence overlays for details that are better shown as pause-readable examples than spoken aloud.
- Audio/voice style when relevant.

Minimum B2B structure:

- Hook: name the institution pain.
- Pain scene: show why the pain is expensive or urgent.
- Boundary: explain what 科创赛考 is not.
- Solution logic: show product-line or成果路径.
- Fit timing: when it is suitable.
- Low-risk next step: trial camp, diagnosis, pilot, or方案沟通.

Quality bar:

- The script must be checked before rendering to ensure it speaks to B-end owners.
- The first 3 seconds should combine a Douyin/Xiaohongshu-style hook with B2B filtering: name a pain, challenge an assumption, show a contrast, or reveal a business opportunity. Do not rely on a static cover plus narration.
- Avoid long subtitles. Prefer short scene headings, step labels, and logical cards.
- If concrete cases are useful but too long for the voiceover, design them as pause-readable overlays or dedicated logic-card moments. Mark hypothetical examples as typical scenarios instead of implying real proof.

## Deliverable 8: Rendered Short Video

Use when the user asks to produce, render, or make the video.

Default format:

- Vertical 9:16, 1080 x 1920 for Xiaohongshu/Douyin unless otherwise requested.
- Use local Kokoro voiceover by default when narration is needed, following workspace video preferences.

Hard requirements:

- Do not make a one-image video unless the user explicitly asks for a static poster video.
- The approved cover should be integrated as the first frame of the video unless the user explicitly requests a different opening.
- Design the first 3 seconds deliberately as an opening hook that combines picture, voice, and on-screen copy. It should show a clear change, question, contrast, or business signal before the viewer swipes away.
- Use multiple scenes or dynamic logic states: diagnosis, comparison, path map, checklist, timeline, flow, or project evidence.
- Segment narration by scene and align scene durations to segment-level audio timing.
- Avoid large subtitle blocks. On-screen copy should be short, readable, and integrated into the visual logic.
- Text backgrounds must be generated from measured text size and line count; no fixed-size panels for variable text.
- If a cover is used at the start, use the approved current cover, not an obsolete previous version.

QA:

- Confirm video duration, resolution, video codec, and audio track.
- Confirm audio is not silent with a volume check or equivalent.
- Inspect the first 3 seconds separately for hook strength: picture, voiceover, and on-screen text should reinforce the same B-end buyer problem or opportunity, with visible motion or information change.
- Inspect key frames from every scene, not arbitrary intervals that miss scenes.
- Check text overflow, panel fit, and whether any text/panel covers core people or objects.
- Confirm the video has meaningful visual changes during long voiceover segments.

## Deliverable 9: Platform Adaptation

Use when adapting one approved content idea from one platform to another.

Must preserve:

- Approved title or hook.
- Approved target institution and pain.
- Approved lead-quality filter.

May adapt:

- Aspect ratio.
- Layout.
- Text density.
- Supporting line.
- Visual composition.
- CTA softness and compliance wording.

Quality bar:

- Adaptation is not rewriting strategy.
- Never silently replace a proven cover title with a new explanatory title.

## Deliverable 10: QA Report

Use when the user asks to check or when delivering generated visual/video artifacts.

Must state:

- Which files were inspected.
- Which platform requirements were checked.
- Which visual risks were checked: text overflow, subject occlusion, safe area, line breaks, audio, scene variation.
- Any remaining known limitations.

Do not claim "final" if visual inspection was not performed.
